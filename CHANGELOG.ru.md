# История изменений

[English](CHANGELOG.md) · [Русский](CHANGELOG.ru.md)

Здесь описаны все значимые изменения AdaptForm. Раздел `2.1.0` подготовлен к выпуску, но остаётся неопубликованным до публикации сопровождающим проекта.

**[Интерактивное демо](https://arhimen.github.io/AdaptForm/?lang=ru)** · [Исходный код демо](https://github.com/ArhiMEN/AdaptForm/tree/master/demo) · [Документация](https://github.com/ArhiMEN/AdaptForm/blob/master/README.ru.md)

## [2.1.0] — Не выпущено

### Добавлено

- Локализация демо на английский и русский с сохранением выбранного языка и ссылками на документацию соответствующего языка; введённые значения и состояние валидации сохраняются.
- Полные русские версии документации, истории изменений, плана выпуска, журнала статуса, инструкций репозитория и сведений о лицензии рядом с английскими оригиналами.

- Интерактивное демо в браузере: валидация полей, условная обязательность, состояния полей, массивы, вложенные формы, серверные ошибки, сериализация и маски ввода.
- Workflow GitHub Actions для сборки и публикации демо в GitHub Pages из `v2.1.0` и `master`.
- Отдельные команды проверки типов и производственной сборки демо, выполняемые в CI.
- Автоматическая проверка состава npm-пакета: обязательные ESM, CommonJS и декларации TypeScript включены, исходный код разработки и тесты исключены.
- Экспорт `ErrorsSchema` из публичной точки входа пакета.
- Вывод типов `Form.fieldsValue` из объявленных свойств `Field`, `ArrayField` и `ArrayFormField`.

### Изменено

- ESLint настроен для TypeScript-кода библиотеки, тестов и демо; lint и аудит зависимостей выполняются в CI на Node.js 22.
- Обновлены Vitest, Vite, ESLint и инструменты lint для TypeScript; закреплены исправленные транзитивные зависимости и согласован lockfile.
- Абсолютный путь в псевдониме Vitest заменён переносимым путём относительно проекта.
- Значения непосредственных полей присваиваются до проверки формы, чтобы условные правила видели полное состояние без двойного запуска валидаторов этих полей.
- Добавлены `Form.setFields(data, validate?)` и `Field.setRawValue(value, validate?)` для управляемого присваивания с необязательной отложенной валидацией.
- Уточнён сброс: значения по умолчанию восстанавливаются без вызова пользовательских валидаторов, ошибки очищаются, корректность не определена до следующей проверки.
- При назначении нового ответа ошибок предыдущие серверные ошибки очищаются рекурсивно.
- Коллекции проверяются после изменения, чтение `ArrayFormField.isValid` не вызывает скрытую повторную валидацию, некорректные индексы удаления игнорируются, после сброса корректность ожидает новой проверки.
- Улучшены выведенные типы значений формы, nullable-значения массивов, типы коллекций вложенных форм и результаты JSON-сериализации.
- Массивы и вложенные объекты кодируются в JSON в `FormData`; `null`/`undefined` пропускаются; `Blob`/`File` сохраняются; вложенные JavaScript `Date` рекурсивно преобразуются в ISO 8601 в JSON.
- README переписан для описания API, жизненного цикла валидации, параметров коллекций, сопоставления ошибок, сериализации, команд разработки и интерактивного демо.

### Исправлено

- Проверка строк стала детерминированной для регулярных выражений с глобальным или липким флагом.
- `NumberType` отклоняет пустые и неконечные значения.
- Десятичные числа с избыточной точностью отклоняются без скрытого округления; `decimalPlaces: 0` обрабатывается корректно.
- Строки только из пробелов считаются пустыми; значения по умолчанию конструктора сохраняют состояние «не изменено».
- Исправлена условная обязательность после массового присваивания полей формы.
- Валидация массива обновляется после добавления элементов/форм; отрицательные, дробные и выходящие за границы индексы удаления игнорируются.
- `ErrorsSchema.forArray()` учитывает пользовательский извлекатель индекса, правила и преобразования схемы элемента, поддерживает скобочную, точечную и пользовательскую запись индекса.
- Обработчик fallback в `ErrorsSchema` вызывается только один раз, если он отклоняет ошибку.
- Исправлен тест граничного времени; добавлены проверки сброса, очистки вложенных ошибок, группового присваивания, nullable-массивов, сериализации Date и обработки Blob/File.

### Безопасность и сопровождение

- Проверка состава пакета поддерживает JSON-манифесты npm pack в виде массива и объекта с ключами; документация пакета обязательна на английском и русском.

- В CI добавлен `npm audit --audit-level=moderate`; уязвимые транзитивные зависимости обновлены проверенными overrides. Последний проверенный workflow сообщает о нуле известных уязвимостей в npm audit; предыдущая проверка lockfile также сообщила о нуле.
- В CI проверяются lint, тесты, сборка ESM/CJS, декларации, типы библиотеки, типы и сборка демо, состав npm-пакета.

### Совместимость

- Встроенные сообщения валидации библиотеки и их язык в этом кандидате не изменены. Их локализация и контракт структурированных кодов ошибок отложены до отдельной согласованной задачи.
- Интеграция с PlayLease явно исключена из области этой ветки.
- Эта история описывает кандидата в ветке `v2.1.0`; публикация npm-пакета и выпуск на GitHub остаются действиями сопровождающего проекта.

## [2.0.5] — 2026-07-22

### Добавлено

- Класс `ErrorsSchema` для гибкого разбора и сопоставления серверных ошибок
- Статическое сопоставление точных ключей через `staticKey()`
- Динамическое сопоставление через `dynamicKey()` с регулярными выражениями и приоритетом
- Обработчик `fallback()` для ключей без соответствия
- `transformValue()` для нормализации сообщений (массив в строку, удаление префиксов и т. п.)
- Метод `parseErrors()`, возвращающий плоский `Record<string, string>`
- Метод `parseErrorsDetailed()`, возвращающий объекты `ParsedError` с метаданными (sourceKey, matchedBy)
- Метод `nest()` для схем с префиксами вложенных форм
- Методы `clone()` и `merge()` для композиции и повторного использования схем
- Фабрика `ErrorsSchema.fromObject()` для быстрого сопоставления из обычного объекта
- Фабрика `ErrorsSchema.forArray()` для шаблонов ошибок массивов полей
- Готовые схемы: `DefaultErrorSchema`, `LaravelErrorSchema`, `GraphQLErrorSchema`
- Система приоритетов динамических правил для управления порядком сопоставления
- Цепочка преобразователей значений для последовательной нормализации сообщений
- Рекурсивный разбор вложенных объектов ошибок
- Встроенная поддержка ошибок в формате Pydantic

### Изменено

- Сеттер `Form.errors` использует `ErrorsSchema` для сопоставления ошибок
- Добавлено свойство `Form.errorsShema` для настройки схемы отдельной формы
- `Form.applyErrorToField()` поддерживает вложенные пути (например, `accounts.0.email`)
- `Form.applyNestedError()` рекурсивно обрабатывает `ArrayFormField` с правильным контекстом
- Геттер `Form.allErrors` рекурсивно собирает ошибки вложенных `ArrayFormField`
- `Form.reset()` очищает ошибки всех полей и общие ошибки
- Пустой объект ошибок очищает все ранее применённые ошибки
- Общие ошибки привязаны к соответствующему экземпляру формы
- `DefaultErrorsSchema` использует `fallback((key) => key)` для обратной совместимости

### Исправлено

- Передача вложенных ошибок `ArrayFormField` при индексах за границами массива
- Контекст ошибок при назначении полям вложенных форм
- Отсутствие ошибок вложенных форм `ArrayFormField` в `allErrors`
- Неполная очистка общих ошибок при назначении новых
- Неожиданное поведение при значениях ошибок null/undefined
- Сопоставление ошибок массивов полей (ArrayField) по индексным ключам

## [2.0.0 - 2.0.4] — 2026-05-29

### Добавлено

- Полная переработка на TypeScript с выводом типов
- Система плагинов MaskPlugin, FieldPlugin и DecoratorPlugin
- ArrayField для динамических массивов полей
- ArrayFormField для массивов вложенных форм
- Новые типы: DecimalType, DateLuxonType, BooleanType
- Необязательная интеграция Luxon через экспорт `adaptform/luxon`
- Маски ввода с гибкой настройкой
- Условная обязательность полей в зависимости от состояния формы
- Пользовательские сообщения валидации для всех типов полей
- Общие ошибки для ответов сервера
- Сериализация форм (`toJSON()`, `toFormData()`)
- Экспорты с поддержкой tree shaking для уменьшения сборок
- Поддержка ESM и CJS
- Полные декларации TypeScript с корректными типами

### Изменено

- **Полная переработка API** — новая архитектура на основе классов
- Поля создаются через `new Field(TypeClass, defaultValue, options)`
- Валидация требует явных объявлений полей в теле класса
- Система плагинов заменяет прежний механизм middleware
- Обработка ошибок унифицирована для всех типов полей
- Методы валидации возвращают массивы строк вместо boolean
- Интерфейс параметров перестроен для улучшения вывода типов

### Несовместимые изменения

- **Полная переработка относительно v1.x** — обратная совместимость отсутствует
- Форма должна наследовать базовый класс `Form` и объявлять поля
- Конструктор поля требует TypeClass первым аргументом
- `validate()` возвращает `string[]` вместо `boolean`
- API плагинов полностью переработан
- Пути импорта изменены для поддержки tree shaking
- Тип даты Luxon вынесен в отдельную точку входа `adaptform/luxon`

### Удалено

- Прежний API на основе функций
- Старый механизм middleware для валидации
- Глобальная конфигурация singleton
- Автоматическая зависимость от Luxon (теперь необязательна)
