# Выборочные проверки

[English](SKILL.md) · [Русский](SKILL.ru.md)

Применять при выборе проверок для ограниченного изменения или диагностике упавшей проверки проекта.

- Прочитать `package.json`, список изменённых файлов и только нужные пути тестов. Следовать правилам команд из `AGENTS.md`.
- Сопоставлять поведение ядра с `tests/unit/`, взаимодействия с `tests/integration/`, поведение демо с `tests/demo/`; начинать с минимального подходящего файла Vitest.
- Расширять проверки только при обосновании областью изменений или результатами. Выбирать проверки типов, сборки и пакета для затронутых контрактов; покрытие использовать при необходимости.
- Для изменений только документации или конфигурации агентов проверять Markdown, локальные ссылки, согласованность языков, frontmatter skills и `git diff --check`; по умолчанию не запускать тесты библиотеки.
- Указывать точные команды и успешные, неуспешные, пропущенные и невыполненные проверки. Запуск без тестов не подтверждает поведение.
