# Граница адаптера фреймворка

[English](SKILL.md) · [Русский](SKILL.ru.md)

Применять только для явно согласованной задачи проектирования или реализации адаптера фреймворка; сам skill не согласовывает адаптер.

- До изучения фреймворка прочитать согласованную область задачи и `docs/ai/DECISIONS.ru.md`. Если реализация отдельно не согласована, записать предложение и остановиться до изменения кода.
- Определить минимальное отображение событий или реактивности фреймворка на существующие API Field/Form. Оставить валидацию и приведение типов в библиотеке.
- Держать зависимости фреймворка вне основной точки входа; не добавлять зависимости или новый публичный контракт без явного согласования.
- Описать обновление значений, момент валидации, ошибки, сброс и освобождение ресурсов, где применимо. Сопоставлять с существующим жизненным циклом, не создавать параллельные правила.
- Выбирать точечные проверки адаптера и интеграции только после согласования целевого фреймворка и поведения; не создавать заготовки неиспользуемых адаптеров.
