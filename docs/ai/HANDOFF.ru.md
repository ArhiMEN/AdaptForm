## HF-002 — Отложенная валидация ArrayField — 2026-10-17

**Завершено:** присваивание коллекции откладывает валидацию через `Form.setFields(data, false)`; при включённой проверке каждая коллекция проверяется один раз после присваивания всех значений формы, с родительской формой в контексте.

База: актуальный `origin/master` на `77ae564b7a87d967f5700aa676d4735d7f00687d`. Ветка: `fix/hf-002-arrayfield-deferred-validation`. Создать PR в `master`; автоматически не объединять.

### Изменения и совместимость

- `src/core/fields/ArrayField.ts`: `itemsValue` делегирует присваивание `setItemsValue(items, validate = true)`. Замена очищает прежние ошибки/результат коллекции без проверки промежуточного пустого массива. Публичный setter по-прежнему немедленно проверяет готовую коллекцию.
- `src/core/Form.ts`: значения ArrayField присваиваются с отключённой проверкой; существующая итоговая проверка формы отвечает за валидацию с родительским контекстом.

### Ограничения и следующее действие

Ненулевые значения по умолчанию конструктора Field по-прежнему валидируются при создании элементов, в том числе при отложенном присваивании; HF-002 подавляет проверки, запускаемые коллекцией, а не конструктором. Отложенная замена очищает ошибки коллекции и оставляет её валидность false до явной проверки; состояние элементов после конструктора сохраняется. Существующие вопросы границ Decimal, состава коллекции после reset и агрегации touched остаются вне задачи.
