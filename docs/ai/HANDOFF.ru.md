### Подтверждённое поведение

- `Field.setRawValue(value, false)` всё равно приводит тип, отмечает touched, очищает прежние ошибки и устанавливает validity в `null`; проверки типа, обязательности и пользовательская валидация ждут явного запуска. Неудачное приведение даёт null в очищенном значении без немедленных ошибок.
- `Form.setFields(data, false)` откладывает проверки прямых полей, сохраняет пропущенные поля и глобальные ошибки, отмечает присвоенные поля touched. Обычное массовое присваивание проверяет прямые поля один раз с полными новыми значениями соседей. Чтение `isValid` само по себе не перезапускает эти валидаторы.
- `ArrayField.itemsValue` проверяет промежуточную пустую коллекцию, затем пересозданную, без контекста родителя. Для необязательной коллекции с пользовательским валидатором и одним ненулевым элементом валидатор элемента вызывается дважды: в конструкторе и при проверке коллекции. Через `setFields(..., true)` третья проверка элемента и финальная проверка коллекции получают контекст родителя. При `false` преждевременные проверки всё равно происходят: коллекция может быть валидной, пока validity прямого соседнего поля остаётся null.
- Программная непустая замена коллекции отмечает её touched, но новые элементы ArrayField остаются нетронутыми значениями конструктора. Удаление/очистка нетронутого ArrayField не отмечает его touched.
- Гидратация ArrayFormField с null-значениями полей по умолчанию откладывает валидацию; проверка родителя валидирует их один раз с собственной дочерней формой в контексте. Ненулевые значения класса по умолчанию валидируются в конструкторе дочерней формы даже при отложенной гидратации.
- Изначально гидратированные дочерние формы отмечены touched, но их ArrayFormField и родитель могут оставаться нетронутыми. Последующее прямое присваивание дочернему полю не передаёт touched через эту нетронутую коллекцию. Валидность дочерних полей всё равно влияет на родительскую.
- Сброс обеих коллекций сохраняет текущие объекты и порядок: удалённые элементы не возвращаются, добавленные остаются. ArrayField восстанавливает значение конструктора каждого сохранённого элемента; ArrayFormField восстанавливает значения класса по умолчанию (null для полей без значения), а не данные гидратации. Ошибки и глобальные ошибки дочерних форм очищаются, touched сбрасывается, валидность коллекции остаётся false до проверки; reset не вызывает пользовательские валидаторы.
- Десятичные строки остаются строками, обрезаются пробелы и нормализуется запятая; числовой ввод остаётся числом. Некорректный формат приводится к null, лишняя точность отклоняется без округления, ограничения целой части сохраняются, завершённые значения соблюдают включительные/исключительные границы. Завершающая точка обходит **все четыре числовые границы**, может пройти `Form.checkValid()` и сохраняется в `toJSON()`.

### Воспроизведения и будущие регрессионные ожидания

Запускать из репозитория с `export npm_config_cache=/workspace/.npm`. Для изолированного воспроизведения перед каждым фильтром ниже ставить `npx --no-install vitest run tests/unit/form-lifecycle-baseline.test.ts -t`. Все текущие утверждения фиксируют существующее поведение и проходят.

| Фильтр | Минимальное воспроизведение / граница будущей регрессии |
| --- | --- |
| `'ArrayField assignment validation'` | Необязательный ArrayField со spy коллекции/элемента; присвоить `['new']` напрямую или через `setFields({ values: ['new'], sibling: 'ready' }, false/true)`. Наблюдаемые состояния коллекции: пустая, пересозданная, затем с родительским контекстом только при включённой проверке. HF-002 должен проверять отсутствие преждевременных вызовов коллекции при false и одну финальную проверку с родителем при true; отдельно учитывать валидацию в конструкторе фабрики. |
| `'decimal input and submission'` | `new Field(DecimalType, null, { le: 122 })` принимает `'123.'`, отклоняя `'123'`; аналогичный обход есть для gt/ge/lt. Будущий тест безопасной отправки должен отклонять выходящее за границу значение с завершающей точкой только после согласования политики HF-003; политику редактирования сохранять осознанно. |
| `'collection reset after structural changes'` | Создать два элемента, удалить один, добавить другой, изменить, сбросить. Текущий состав сохраняется; вложенные формы возвращаются к значениям класса по умолчанию. Будущий тест восстановления исходного состава/гидратации требует согласования HF-004. |
| `'nested form assignment and state'` | Гидратировать дочернюю форму ArrayFormField или изменить её напрямую: touched дочерней формы может быть true при touched родителя false. Будущая семантика агрегации требует согласования HF-005. |
