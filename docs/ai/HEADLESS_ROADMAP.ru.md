## Целевое устройство

- Классы `Form` / `Field` остаются публичным API; UI (Vue/React/Electron) подключается через необязательные адаптеры.
- Узлы формы хранят исходный ввод, нормализованное значение, baseline, состояние проверки и ошибки; родитель агрегирует состояние дочерних узлов.
- Собственные подписки с выбором данных, стабильные snapshots, синхронные batch-транзакции и одно уведомление после commit; без обязательного RxJS/Vue/React.
- Явные зависимости валидаторов, единый жизненный цикл коллекций, идентификаторы элементов, проверка async-результатов по версии и необязательный submit lifecycle.
- Без приватных данных, ключей, логов значений полей, автоматического npm publish и внезапных breaking changes.

## Решения, требующие согласования

- Семантика touched/dirty/baseline и совместимость reset определены HF-005. Состав reset коллекций и reinitialize остаются отложенными.
- Двухфазная валидация незавершённых чисел вроде `123.`, формат `valueClear`, финальная проверка при submit.
- API подписок/snapshots и исключения batch определены HF-005–HF-010. Циклы зависимостей, политика ошибок и триггеров требуют будущего решения.
- Отмена async-проверок, повторный submit; пакеты/входные точки адаптеров.

## Этапы

- **P0: Стабилизация контрактов** — Тесты и воспроизведение проблем до изменения поведения.
- **P1: Состояния и уведомления** — Dirty/baseline, snapshots, batch, вложенные подписки и идентичность коллекций.
- **P2: Интеллектуальная валидация** — Явные зависимости, триггеры и структурированные ошибки.
- **P3: Async и отправка** — Асинхронные проверки без гонок и пользовательский обработчик отправки.
- **P4: Интеграция и контроль качества** — Дизайн и пилот Vue, измеряемая приёмка.
