## Идентичность и snapshots

Сохраняемый экземпляр Field/Form имеет один стабильный локальный строковый ID, независимый от значения и индекса. Общий WeakMap использует объекты как ключи, не значения элементов, и не удерживает удалённые узлы. Новые независимые экземпляры (включая равные по значению) получают разные ID. ID выделяются при первом capture snapshot, не переиспользуются в загруженном модуле и не переносятся между перезагрузками, копиями engine и сериализацией. Разным элементам нужны разные экземпляры: фабрика приложения, возвращающая один и тот же Field, создаёт alias одного узла, как раньше; это не два независимых значения. Нового запрета таких исторических фабрик нет.

Snapshots обеих коллекций теперь включают frozen ordered `itemIds`, параллельный `items` / `forms`. Свойство экспортируемого интерфейса опционально для совместимости со структурными producers snapshots 2.2.0; engine всегда его заполняет. Потребитель расширенного интерфейса должен учитывать `undefined`. ID не добавляются в дочерние snapshots, fieldsValue, JSON и FormData. Форма snapshot получает metadata; потребители с проверкой точного набора ключей должны учитывать добавление. Неизменённое состояние сохраняет ссылку snapshot. Замена или перестановка равных по значению узлов теперь меняет snapshots коллекции/предков и уведомляет наблюдателей, поскольку изменилась идентичность.

Связи владения основаны на объектах, не индексах. Move сохраняет подписки и baseline дочернего узла. Remove/replacement/clear немедленно сверяют связи наблюдения, включая batch. Удалённые узлы остаются пригодными для работы и могут сохранять собственных подписчиков, но не уведомляют прежних родителей. Последняя отписка освобождает рекурсивные связи. API destroy/dispose и гарантия немедленного GC не вводятся.

## Аддитивные операции

```ts
const tags = new ArrayField((value?: string) => new Field(StringType, value), {}, ['a', 'b'])
const retained = tags.items[1]
const id = tags.getSnapshot().itemIds?.[1]
tags.insert(1, 'new', false) // Field<string> | undefined; вставка перед индексом
tags.move(2, 0)             // конечный порядок: b, a, new
retained === tags.items[0]  // true
tags.getSnapshot().itemIds?.[0] === id // true
```

| API | Контракт |
| --- | --- |
| ArrayField.insert(index, value?, force_check = true) | Field<T> или undefined; фабрика, touched и validation как у add |
| ArrayFormField.insert(index, data?, force_check = true) | T или undefined; конструктор/hydration/child baseline/touched как у add |
| Оба move(from, to): void | Переставляет тот же узел на конечный индекс; запрашивает одну автоматическую валидацию |

Insert принимает целые индексы `0..length`, включая пустую коллекцию и append. Move принимает целые `0..length-1` для обоих аргументов; корректировка индекса после удаления не применяется. Отрицательные, дробные, NaN, бесконечные и выходящие за диапазон индексы дают no-op без конструирования, валидации, изменения touched и событий. Move с одинаковыми индексами тоже no-op. Move не присваивает touched, аналогично существующему remove; insert присваивает его как add. Сигнатуры и возвращаемые значения add, а также setters сохранены. Автоматическая валидация синхронна вне batch и откладывается/объединяется внутри Form.batch; явные проверки остаются немедленными. Завершённые структурные записи не откатываются при исключениях.

## Значения, ошибки и совместимость

Dirty/baseline по-прежнему сравнивает упорядоченное очищенное содержимое и dirty потомков без ID. Возврат неравного содержимого к порядку baseline даёт clean; перестановка равных значений остаётся clean, хотя ID и snapshots меняются. Семантика `commitBaseline()` и `reset()` сохранена; reset действует на оставшиеся узлы и не восстанавливает состав/порядок. `setItemsValue()` / `setForms()` создают замену без сопоставления старых узлов по значению. Новый объект получает новый ID даже при равных payload.

Metadata ошибок хранится на узлах; агрегаты строятся в текущем порядке массива. Существующие пути серверных ошибок ArrayFormField (`rows.1.name`) разрешают **текущий** индекс в момент присваивания; Form.allErrors подписывает текущие позиции. Move использует обычную автоматическую валидацию, способную пересобрать/очистить прежние validation/server errors, как remove. Ошибки элементов ArrayField доступны на узлах/snapshots; его ранее неподдерживаемые серверные dot paths остаются global errors. Произвольные глобальные строковые ключи ошибок не привязываются заново и не переиндексируются. Новый формат и маршрутизация ошибок не вводятся.

Прямые записи в исторические mutable-массивы `items`/`forms` остаются вне автоматического наблюдения. Обновление при чтении может их обнаружить; для структурных событий следует использовать insert/move/add/remove. Перенос/adoption между коллекциями, setters сохраняемых экземпляров, сохраняемые ID и публичные ссылки на узлы для dependency graph — отдельные темы проектирования.

Regression coverage: вставка/удаление/перестановка обеих коллекций; равные значения; вложенные сохраняемые узлы; конечная batch-валидация/контекст; подписки до/после удаления; индексные nested errors; scalar item errors; frozen/stable snapshots; полная замена и сериализация; dirty/baseline/reset; некорректные индексы и границы append/empty. См. [проверки](../roadmap/v2.3.0/VERIFICATION.ru.md).
