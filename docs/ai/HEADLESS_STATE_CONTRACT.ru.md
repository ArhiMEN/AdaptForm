## Источники и производные состояния

Field хранит исходный ввод, кешированное очищенное значение после плагинов и приведения типов, ошибки, прежний изменяемый isTouched и isValid: null — не проверено, true — принято, false — отклонено. Baseline — независимая копия очищенного значения после конструктора. isDirty сравнивает его с кешированным текущим значением, не вызывая приведение или валидацию. Разные ошибочные вводы, очищенные до null, одинаковы для dirty, но различимы в snapshot.

Form вычисляет валидность и touched по прежним правилам, dirty — по потомкам. Коллекции дополнительно сравнивают упорядоченное очищенное содержимое с исходным baseline: добавление, удаление, перестановка и замена отражаются в dirty. Возврат равного содержимого в прежнем порядке очищает dirty; стабильные идентификаторы не вводятся. Первичная гидратация ArrayFormField фиксируется как baseline коллекции независимо от значений классов для reset. Учитывается также dirty потомков, включая явную фиксацию их baseline.

Вложенность использует существующее владение через ArrayFormField. Focused, visited, pending, submission и async не реализуются. Независимой изменяемой копии aggregate validity/dirty нет.

## Переходы

| Операция | Значение | Touched | Валидность/ошибки | Baseline/dirty |
| --- | --- | --- | --- | --- |
| Конструктор | Прежние default/plugin/cast | false, прежние правила коллекций | Прежняя проверка default | Копия clean |
| Присваивание с проверкой | Одно приведение | true, в том числе программно | Прежняя синхронная проверка | Сравнение с baseline |
| Присваивание без проверки | Одно приведение | **true** | null, ошибки Field очищаются | Сравнение с baseline |
| checkValid | Без изменений | Без изменений | Пересборка ошибок; Field не присваивает isValid | Без изменений |
| checkAndSetValid | Без изменений | Без изменений | Пересборка ошибок и isValid | Без изменений |
| Серверная ошибка | Без изменений | Без изменений | Прежний setter | Без изменений |
| reset | Default сохранившихся узлов | Прежний сброс | Очистка ошибок и проверки | Baseline сохраняется |
| commitBaseline | Без изменений | Без изменений | Без изменений | Рекурсивно фиксирует текущее значение |

Touched отражает прежние присваивания/взаимодействия, а не отличие от baseline и не исключительно ручной ввод. Изменение форматирования может менять touched и snapshot без dirty. Ошибки независимы от dirty. После фиксации иного baseline reset может оставлять dirty: он возвращает значения конструктора. Reset не восстанавливает состав/порядок коллекций; HF-004 исключён.

reinitialize(data) отложен: будущее предложение должно атомарно присваивать данные и фиксировать baseline с явными настройками проверки/touched и отдельным выбором цели reset. Метод здесь не реализуется.

## Сравнение значений

Структурное сравнение без JSON.stringify: примитивы через Object.is, Date по времени, массивы, обычные объекты со строковыми ключами, Map/Set в порядке обхода, RegExp и бинарные буферы/представления. Копирование отделяет изменяемые контейнеры; циклы поддерживаются. Luxon DateTime сравнивается семантически без зависимости ядра от Luxon. Остальные экземпляры классов непрозрачны и сравниваются по ссылке; для наблюдения требуется присваивание. Symbol/неперечисляемые свойства и внешние изменения исходных массивов/ошибок автоматически не отслеживаются.

## Подписки и snapshots

Все четыре класса используют общую синхронную инфраструктуру. subscribe(listener) возвращает идемпотентную отписку; аргументы с данными не передаются, чтение — через getSnapshot(). Начального уведомления нет. Snapshot сохраняет ссылку при равном наблюдаемом состоянии; данные отделены и рекурсивно заморожены. Он содержит raw/clean по типу узла, validity, errors, touched, dirty и snapshots потомков. Чтение не валидирует. Date и другие изменяемые встроенные типы представлены неизменяемыми описаниями; произвольные классы/функции/символы — непрозрачными описаниями без внутренних ссылок. Публичные типы отражают эти представления.

Одна завершённая операция библиотеки даёт максимум одно уведомление затронутому узлу. Изменения только ошибок/touched/validity наблюдаемы. subscribe/getSnapshot обнаруживают поля после инициализации подкласса. Изменение состава коллекции обновляет владение, удалённый узел теряет родительскую связь. Последняя отписка рекурсивно освобождает связи; следующая подписка восстанавливает их. Произвольная замена свойства Form, внешние изменения прежних массивов/options и внутренностей custom value не перехватываются Proxy: для обновления нужна операция библиотеки или последующее чтение.

## Batch

form.batch(callback) синхронен и поддерживает вложенность. При исключении уже выполненные изменения не откатываются: уведомления завершаются, исключение передаётся вызывающему. Вне batch проверки сеттеров остаются синхронными. В явном batch автоматические проверки отложены до полного присваивания с контекстом внешней Form; явные вызовы валидаторов выполняются сразу и могут видеть промежуточные данные. Итоговые проверки объединяются без графа зависимостей. getSnapshot() внутри batch возвращает последний завершённый snapshot; обычные getters показывают текущие значения. Асинхронные callback не поддерживаются, await выполняется вне batch.

## Ограничения и будущее

Сравнения/snapshots обходят значения, стоимость линейна по объёму, результаты benchmark не заявляются. Валидаторы должны избегать мутаций/циклов. Не включены dependency discovery, rollback, async fencing, стабильные ID, submit и адаптеры (HF-011+). Нужны независимое ревью, CI и отдельная подготовка релиза.
