## Синхронная граница

Небольшой модульный контекст теперь ограничен получателем/ключом, а не всеми ручными записями на стеке. Вложенный импорт заменяет/восстанавливает его; исключения всегда восстанавливают контекст. Повторные superclass-вызовы того же получателя/ключа внутри вызванного сеттера намеренно считаются частью серверной операции, включая преобразованные сообщения. Произвольная рекурсивная запись в тот же сеттер/ключ не передаёт отдельного намерения вызывающего кода; когда различие существенно, используйте явный локальный `setErrors(inputs, source)`. Другие узлы/ключи и callbacks после выхода из области получают `external`. Уведомления публикуются после внешней синхронной мутации, поэтому reentrant-подписчики начинают работу после восстановления контекста.

Это мост синхронной диспетчеризации, не async-контекст. Его нельзя удерживать через `await`; отложенные записи имеют external-происхождение, если источник не задан явно. HF-016 потребует явно принадлежащего операции результата и политики устаревших результатов. HF-016, AsyncLocalStorage и новые зависимости не добавлялись.

Manifest/lockfile побайтово одинаковы; агрегированные родительские находки могут различаться между запусками audit. [Production-only audit](hf015-review/audit-production.json): **ноль уязвимостей**.

Цепочка: прямая dev-зависимость `jsdom@29.1.1` → `undici@^7.25.0`, принудительно закреплённая корневым `overrides.undici = 7.29.1`; Vitest также использует jsdom как optional peer. Production runtime не подключает undici. Минимальное исправление всех восьми наблюдаемых диапазонов: **undici 7.30.1**, версия существует и не имеет известных находок по [NPMScan](https://npmscan.com/package/undici) и диапазонам npm advisories. Install/preinstall/postinstall scripts не обнаружены. Чистый lookup относится к моменту проверки и не является гарантией.

Предложение для отдельного согласования:

1. Изменить только `overrides.undici` **7.29.1 → 7.30.1**, сохранить **jsdom 29.1.1**, Vitest и остальные прямые версии. Обновить соответствующие resolution/integrity lockfile и проверить отсутствие посторонних изменений. Обновление одного jsdom не обойдёт текущий override.
2. Выполнить чистый `npm ci`, оба audit и полный существующий набор lint/test/type/build/package/demo/packed-проверок, включая CI Node 22. Не менять workflow/пороги/исключения.
3. Проверить поведение HTTP/fetch/resource-loader jsdom. У обеих версий undici сохраняется `engines.node >=20.18.1`; jsdom уже требует `^20.19.0 || ^22.13.0 || >=24.0.0`. Это не повышает dev Node floor или заявленный runtime floor библиотеки **Node >=16**; локально проверен Node 24, не исчерпывающая матрица версий Node. Упакованный core не требует undici или Luxon.

План не выполнялся: зависимости и lockfile не менялись, security gate не обходился. Оставшиеся ограничения приёмки: красный audit CI до отдельного согласования, разброс времени общего хоста, неоднозначность одинаковых старых строк и намерений одного сеттера, только синхронное происхождение, отсутствие async/stale-result fencing. Независимая приёмка кода возможна с этими явными ограничениями; merge должен дождаться отдельного решения audit gate и проверки итогового head.
