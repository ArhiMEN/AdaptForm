# STAB-02 — измерения headless engine

[English](BENCHMARKS.md) · [Русский](BENCHMARKS.ru.md)

База: STAB-01 `51dc501`, версия пакета 2.2.0 сохранена. Полные данные (медиана/min/max каждого случая, число итераций, среда и heap samples): [JSON](benchmark-baseline.json).

```sh
npm ci
npm run build
mkdir -p work
node --expose-gc scripts/benchmark-headless.mjs work/benchmark.json
```

Запускать из корня репозитория. Без `--expose-gc` временные измерения работают, память отмечается недоступной. Нельзя сравнивать новый source с устаревшим dist. Обязательные зависимости и package scripts не добавляются.

Среда: Linux 6.18.55 x64, Intel Xeon Platinum 8573C (3 видимых CPU), Node 24.19.0, V8 13.6.233.17-node.51. Общий cloud runner без привязки CPU и эксклюзивного хоста. Пять операций прогрева, семь измеряемых серий; 1–100 операций в серии выбираются по прогреву с ориентиром 25 мс. Таблица содержит медиану средних серий; разброс есть в JSON. Каждая операция измеряется performance.now (накладные расходы включены), подготовка и очистка fixture исключены. Создание не включает первый snapshot. Первый snapshot каждый раз читает новую форму. Повторные чтения используют прогретую форму. Мутации меняют значения на каждой итерации. `oneField` — корень без подписки; notification cases включают наблюдаемый корень. `batch10` отключает валидацию записей для выделения стоимости мутаций/snapshot; полная автоматическая валидация включена в remove коллекций. Проверены 1/10/100 пустых callbacks и callbacks, читающих committed snapshot (во время доставки чтение не переснимает состояние). Add/remove измеряет пару: add без валидации, remove с существующей автоматической валидацией; коллекция наблюдается. Для глубины используется одна вложенная форма на уровень и leaf со скаляром и двумя элементами массива.

## Выводы и ограничения

Неизменённый snapshot сохраняет ссылку, но чтение всё ещё переснимает и сравнивает состояние; это не O(1). Здесь чтение формы из 1000 полей стоит 4,79 мс. Структурные операции больших наблюдаемых коллекций и рост глубины — существенные проблемы производительности. По исходному коду предполагаемые причины: повторная сверка состава дочерних узлов, агрегатные обходы, capture/freeze/compare и полная валидация. Это гипотеза для профилирования, не измеренная атрибуция аллокаций/стеков. Переписывание scheduler/cache не включено. Следующий шаг: профилировать валидацию 1000 элементов, посчитать reconciliation/capture и предложить кеширование состава/версий на границе commit с сохранением немедленного detach, обновления при произвольном чтении, исключений и reentrant delivery. Пороговые времена CI на общем хосте не задаются.

Регрессии подписок проверяют независимую регистрацию одного callback, идемпотентную отписку, рекурсивную очистку связей после последнего наблюдателя, отписку во время доставки, повторное подключение, немедленный detach внутри batch, работу удалённых узлов и их собственных подписок. Существующие nested lifecycle tests проходят. Runtime-дефект для безопасного локального исправления не выделен; production scheduler сохранён.

С `--expose-gc` после прогрева и каждого workload из 200 циклов create/subscribe/add/remove/edit detached/unsubscribe (глубина 2) два вызова GC дали heapUsed **11 489 392 → 11 533 792 байта** в шести точках (диапазон 11 489 392–11 544 704). Короткое измерение не доказывает отсутствия утечек, удержания callbacks пользовательским кодом, длительно сохраняемых удалённых узлов, native allocations и иных workload. Детерминированные тесты дают более узкое подтверждение очистки связей; срок финализации GC не утверждается.

HF-011 добавляет identity metadata и структурные операции после этой базы; итоговые повторные измерения фиксируются отдельно. STAB-02 не реализует HF-020 и не задаёт SLA производительности.

## Повторное измерение foundation после HF-011

[Итоговые данные](benchmark-foundation.json), коммит измерения `23b88bc`, тот же harness/среда: 1000 полей — создание **1,3319 мс**, первый snapshot **3,8017 мс**, неизменённый snapshot **4,8409 мс**, batch10 **8,9550 мс**, 100 подписчиков с чтением snapshot **5,7124 мс**. Пара add/remove наблюдаемой коллекции из 1000 элементов: fields **164,1700 мс**, forms **244,7660 мс**; изменение leaf на глубине 5 **1,4634 мс**. Heap samples **11 619 080 → 11 667 312 байт**, диапазон **11 619 080–11 677 872**. Разброс и шум общего хоста не позволяют приписать небольшие отличия HF-011. Проблемы больших коллекций/глубины сохраняются; улучшение скорости и доказанное отсутствие утечек не заявляются.
