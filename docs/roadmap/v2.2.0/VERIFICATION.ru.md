## Исправление независимого ревью PR #16 — 2026-10-19

Ревью обнаружило прямые вызовы `checkValid()` в `remove()` и `clear()` обеих коллекций: `ArrayField` и `ArrayFormField`. Все четыре автоматические проверки теперь используют существующий путь `validateAfterMutation(() => this.checkValid())`. Внутри batch участвующий предок проверяется один раз после всех присваиваний с актуальным контекстом владеющей Form; вне batch проверки остаются синхронными без добавления родительского контекста. Явный `checkValid()` выполняется сразу. Остальные контракты HF-005–HF-010, reset, версия пакета и зависимости не изменены; HF-011 не начат.

Проверяются количество вызовов валидаторов коллекции/обязательности/потомков/соседнего поля, контекст владельца, сохранение зафиксированных snapshots внутри batch, отсутствие промежуточных уведомлений и одно итоговое уведомление на изменённый узел. Исходный запуск 30 регрессий воспроизвёл дефект в 26 случаях; четыре проверки вне batch уже проходили. Итоговый набор из 34 случаев проходит, как и все 563 теста.

## Ограничения и следующее действие

Benchmark и универсальное доказательство отсутствия GC-утечек не заявляются: вложенные snapshots собираются и сравниваются повторно, batch проверяет участвующие корневые формы, стоимость растёт с объёмом/вложенностью. Тесты детерминированно проверяют очистку родительских связей и изоляцию удалённых узлов. Snapshot использует union данных и непрозрачные описания неподдерживаемых классов. Прежние внутренние мутации автоматически не перехватываются. См. [примеры](../../ai/HEADLESS_STATE_USAGE.ru.md).
